# Reporting security vulnerabilities

For public repositories, use the affected repository's **Security → Advisories → Report a vulnerability** option to report a vulnerability privately. Include the affected revision, reproduction steps, expected impact, and any suggested mitigation. Do not include live credentials or personal data.

If private vulnerability reporting is unavailable, contact a repository maintainer through an existing private channel and request a secure reporting method. Do not post exploit details or secrets in a public issue.

For private repositories, report to a maintainer in the repository or through your existing private team channel. Rotate exposed credentials immediately; deleting them from a commit is not sufficient.

The default branch is the starting point for security fixes unless a repository specifies supported release branches. This policy does not promise a response or remediation deadline.
