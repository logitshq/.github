# Contributing

Check the repository README for setup, supported environments, and test commands before changing code.

Keep each pull request focused on one change. Explain the problem, resulting behavior, and how you verified it. Include tests for changed behavior when appropriate; for performance claims, include the hardware, workload, baseline, and reproducible command.

Use a feature branch and submit a pull request. Resolve review comments and run the relevant checks before merging. Prefer squash merges with a clear pull request title.

Do not commit credentials, private customer data, model access tokens, or internal logs. Review generated files before adding them. Report vulnerabilities using the security instructions instead of opening a public issue.
